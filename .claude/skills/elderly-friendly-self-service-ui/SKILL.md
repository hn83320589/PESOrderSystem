# 中高齡／非技術客群自助服務介面設計原則

> **狀態：v0.2。** 原則來自單一案例（水電材料批發客戶端，2026-09）：
> - 「核心原則」：客戶轉述其客群反應，**二手推測**。
> - 「採用值」：本案實作並以 390×844 手機尺寸實測，**尚無使用者觀察**。
>
> 兩者都待熟客試用回饋驗證；取得第一手觀察後，更新為實測結論並註明來源。

## 適用情境

客群特徵通常包含以下一項或多項：
- 50 歲以上，平常僅使用 LINE、Excel 等少數固定 App
- 對「設定」「客製化」類功能有抗拒感，怕設定完忘記怎麼用
- 傾向打電話問人，而非自己摸索介面
- 使用手機/平板為主，常從 LINE 聊天室的連結開啟（LINE 內建瀏覽器）

## 核心原則（來自客戶轉述）

1. **用「最近紀錄」取代「自訂設定」**：列出最近幾筆讓他選，而非讓他設定常用項目。
   *依據*：「你要他們去設定『常用組合』，我怕他們設定完就忘記怎麼用了」。
2. **每條操作路徑壓在 1–2 步**：不要有需要先學習才能上手的操作序列。
3. **通知走他們每天在用的管道（LINE）**：App 內小紅點、站內通知只當備份。
4. **防呆優先於漂亮**：送出前預覽、重複送出擋下、按錯可以反悔。
5. **有金錢／庫存影響的動作一律由使用者主動確認**：系統只提醒，不代做決定。
   *依據*：客戶拒絕自動產生訂單——「萬一他剛好不需要那麼多…到時候他說我沒訂啊，那不就變成我自己要吃下來」。
6. **登入用他們已經在用的帳號體系**（LINE Login），不設計帳號密碼。

## 採用值（本案實作，待使用者驗證）

### 版面與尺寸
| 項目 | 採用值 | 做法 |
|---|---|---|
| 基準字級 | 20px | 客戶端根元素 `font-size: 125%`，Tailwind 等 rem 尺寸同步放大，不必逐一調整 |
| 主要按鈕 | 高 ≥ 64px、全寬、粗體；首頁主入口 80px | 一頁只有一個實心主按鈕，其餘為框線按鈕 |
| 數量輸入 | − / 數字 / + 三格，各 56px | 中間仍可直接輸入，聚焦時全選 |
| 版心 | 單欄、最寬 560px、文字靠左 | 手機上等於全寬 |
| 數字 | `font-variant-numeric: tabular-nums` | 金額、數量上下對齊好比對 |
| 購物車 | 固定在畫面底部，顯示項數與金額 | 加 `env(safe-area-inset-bottom)` 避開 iPhone 底部橫條 |

### 用字
- 用他們的講法，不用系統的講法：「叫貨」而非「下單」、「照上次叫的貨」而非「老樣子／歷史訂單」、「待店家確認」而非「pending」、「已取消」而非「已失效」。
- 按鈕寫出按下去會發生什麼：「確定送出（$3,268）」、「要這批貨，送出訂單」、「不要了」。
- 錯誤訊息一律給下一步：說明發生什麼，並附「打電話給店家」按鈕（`tel:` 連結）。
- 訂單編號等要唸給別人聽的字串設 `white-space: nowrap`：實測 390px 寬時會在連字號處斷行。

### 防呆
- **送出前確認頁**做成他們熟悉的紙本單據樣式（本案仿三聯叫貨單），可改數量、刪項。
- **重複送出**：進確認頁即產生一個 UUID 隨請求送出，後端以（客戶, UUID）唯一索引只成立一張單；按鈕送出中停用並改文字「送出中，請稍等…」。本案實測雙擊只成立一張。
- **購物車存在瀏覽器**（localStorage，讀寫包 try/catch）：LINE 來訊息切走、誤關頁面回來都還在。
- **沿用舊單時**：停售品不帶入並列出名稱；改價、缺貨在品項下以黃底文字說明，最後仍需使用者在確認頁送出。
- **客戶送出後不開放自行改單**：引導打電話，避免店家確認前後雙方看到的內容不一致。

### 技術面
- **不載入網路中文字型**：中文字型檔數 MB，LINE 內建瀏覽器＋行動網路會明顯變慢；用系統字型（PingFang TC、Noto Sans TC）。
- **返回鍵**：從 LINE 直接開啟某頁時沒有上一頁，返回鍵改導向首頁。
- **在手機尺寸實測每一頁**（至少 390×844）：本案三個換行問題都只在實測時出現——標題被長客戶名擠成兩行、單號在連字號斷行、三欄選項的五字標籤換行（改為等長的兩三字）。

## 不要做的事（對應上方原則）

- 需要使用者主動維護的「常用組合」「個人化設定」 → 改列最近紀錄
- 只靠站內通知 → 同時推 LINE
- 系統自動成立訂單或扣款 → 提醒後由使用者按確認
- 帳號密碼登入 → LINE Login
