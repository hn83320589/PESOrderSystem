# 中文 PDF 單據產生（Laravel）

> **狀態：draft-v0.1，尚未經過實戰驗證。** 核心待驗證問題：dompdf 與 mpdf 在中文字型支援度上的實際差異，需在第一次實作時比較後選定，並記錄下來避免下次案子重新試錯。

## 何時使用

客戶需要「一張單子」的情境：
- 下單當下自動產生 PDF 訂單
- 補印（重新產生同一份，內容不變）
- 月結對帳單、估價單、收據

## 套件選擇待驗證清單

Laravel 生態常見兩個選擇，實作時需實測後在此記錄結論：

| 套件 | 已知考量點（待實測驗證） |
|---|---|
| `barryvdh/laravel-dompdf` | 較常見、生態成熟，但中文字型需額外嵌入設定，早期版本對中文支援度較弱 |
| `mpdf/mpdf` | 原生對 CJK（中日韓）字型支援較完整，但套件較重、渲染速度可能較慢 |

**待補：實測後在這裡填入結論**——選了哪個、為什麼、遇到什麼問題。

## 中文字型嵌入注意事項（通用原則）

不論選哪個套件，中文 PDF 常見失敗模式：

1. **字型檔案授權問題**：不能隨意用微軟正黑體等商用字型嵌入到可散佈的系統中，需確認字型授權，或改用開源中文字型（如：Noto Sans TC、思源黑體）
2. **字型檔案需明確指定路徑並嵌入**，不能只依賴系統預設字型，否則在沒安裝該字型的伺服器上會顯示空白或方塊
3. **檔案大小**：嵌入完整中文字型檔案會讓 PDF 檔案變大，如果單據數量大，需考慮字型子集化（subsetting）

## 實作骨架（範例，待實測後校正）

```php
// config/dompdf.php 或對應套件設定檔
'options' => [
    'defaultFont' => 'noto-sans-tc', // 需先在設定中註冊字型路徑
],
```

```php
$pdf = Pdf::loadView('orders.pdf', ['order' => $order]);
return $pdf->download('order-'.$order->id.'.pdf');
```

## 補印功能設計原則

補印應該是「重新產生同一份內容」，不是「重新產生一份新單據」：
- 補印時不應變更單號、金額、日期等內容
- 建議做法：訂單資料本身不變，補印只是重新觸發 PDF render，而不是重新計算或修改任何欄位
- 系統應記錄補印次數/時間，方便日後追溯（避免爭議時說不清楚印了幾次）
