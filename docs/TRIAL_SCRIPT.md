# 熟客試用劇本（Step 8）

搭配試用資料 `TrialSeeder` 使用。每個情境的預期結果也由自動測試 `tests/Feature/EndToEnd/TrialScenarioTest.php` 驗證；修改功能後若該測試失敗，請同步更新本劇本。

---

## 0. 準備（開發者，每次試用前）

```bash
php artisan migrate:fresh --seed --seeder=TrialSeeder   # 重建試用資料（約 1 秒），會印出帳號與連結
npm run build
php artisan serve                                       # 網站
php artisan queue:work                                  # 另開視窗：發送 LINE 通知
```

- 排程情境（S7）以手動指令觸發，不必開 `schedule:work`。
- 未設定 LINE 金鑰時，LINE 通知會記為「略過」，其餘流程照常，可以先試。
- 試用資料中的客戶 LINE 帳號是假的。**讓真實熟客用自己的手機試用時**，先在後台「解除綁定」後重新「產生綁定連結」傳給熟客（流程同 S4）。

## 情境

每個情境請記錄：完成與否、花多久、卡在哪、說了什麼。寫進 `docs/feedback.md`。

### S1 工讀生幫熟客電話叫貨（老樣子）
**誰／哪裡**：工讀生，電腦後台
1. 訂單 → ＋代客下單 → 選「永興水電行」
2. 右側「老樣子」選最上面一張 → 帶入
3. 把其中一項數量改掉 → 建立訂單
4. 確認訂單 → 列印訂單 → 標記已出貨

**預期**
- [ ] 付款方式自動帶「匯款」（月結客戶）
- [ ] 印出的 PDF 有匯款帳號、中文正常、長備註有換行
- [ ] 確認後「通知紀錄」多一筆 LINE 通知（未設金鑰時為「略過」並寫明原因）
- [ ] 出貨後「庫存」頁該品項實際庫存減少，「紀錄」看得到佔用與出貨兩筆

**觀察重點**：找客戶、找「帶入」按鈕是否直覺；改數量後合計是否有注意到。

### S2 熟客用手機照上次叫貨，店家確認
**誰／哪裡**：陳師傅（大發）手機 → 工讀生後台 → 陳師傅手機
1. 陳師傅：首頁「照上次叫的貨再叫一次」→ 選一張「照這張再叫一次」
2. 在叫貨單上改一項數量 → 確定送出
3. 工讀生：訂單列表看到「客戶自行下單、待確認」→ 確認訂單
4. 陳師傅：首頁「店家通知」、「我叫過的貨」

**預期**
- [ ] 付款方式預設「付現金」（貨到付款客戶）
- [ ] 送出後畫面顯示訂單編號，編號在同一行
- [ ] 連按兩下送出也只有一張訂單
- [ ] 確認後陳師傅看到「店家已確認」與一則新通知（有設金鑰時 LINE 也會收到）

**觀察重點**：看不看得懂「叫貨單」頁面；會不會找不到送出鈕；是否在意價格調整的黃色提示。

### S3 熟客確認店家預留的貨
**誰／哪裡**：王老闆（永興）手機
1. 首頁黃色框「店家幫您留的貨」→ 確認
2. 選付款方式 → 「要這批貨，送出訂單」

**預期**
- [ ] 首頁清楚看到預留與剩幾天
- [ ] 送出後後台「熟客預留」該筆變「已下單」，庫存的「熟客預留」轉為「已下單未出貨」

**觀察重點**：是否理解「不確認會讓給別人」；會不會想改數量（目前需打電話）。

### S4 新熟客開通（LINE 綁定）
**誰／哪裡**：工讀生後台 → 李小姐手機
1. 工讀生：客戶 → 順利水電工程 → 產生綁定連結 → 複製，用 LINE 傳給李小姐
2. 李小姐：在 LINE 點連結 → LINE 登入同意 → 加官方帳號好友

**預期**
- [ ] 後台客戶列表變「已綁定」
- [ ] 同一連結再點一次會顯示「開通連結已經用過或過期」

> **需要 LINE Login 金鑰與可對外的 HTTPS 網址**（Step 9）。尚未具備時，僅確認後台能產生連結。

**觀察重點**：李小姐是否看得懂 LINE 的同意畫面；有沒有加好友。

### S5 庫存不足
**誰／哪裡**：陳師傅手機
1. 挑商品叫貨 → 電類 → 漏電斷路器 → 3P 50A 顯示「剩不多」
2. 數量按到 6 → 看叫貨單 → 確定送出

**預期**
- [ ] 顯示「漏電斷路器 3P 50A」庫存不足、目前可用 3，訂單不成立
- [ ] 改成 3 後可以送出

**觀察重點**：錯誤訊息看不看得懂、知不知道下一步怎麼做。

### S6 老闆月結收款
**誰／哪裡**：老闆，電腦後台
1. 月結對帳 → 選上個月 → 看永興水電行「本期未收」
2. 點客戶看明細，與紙本或記憶核對
3. 收款 → 篩選永興水電行 → 勾選上個月兩張 → 標記收款（匯款，備註末五碼）
4. 回月結對帳 → 下載 Excel

**預期**
- [ ] 收款後月結報表該客戶本期未收為 0
- [ ] Excel 兩個工作表，0 元顯示為 0 而非空白，合計為公式

**觀察重點**：「本期／前期未收／累計應收」的用詞老闆是否認同；Excel 欄位是否符合他平常對帳的習慣。

### S7 預留到期與提醒（排程）
**誰／哪裡**：開發者執行指令，工讀生看後台
```bash
php artisan reservations:expire   # 釋放已過期的預留
php artisan reservations:remind   # 提醒 7 天內到期的預留
```
**預期**
- [ ] 大發電器行的過期預留變「已到期釋放」，庫存可用量回升 10
- [ ] 永興水電行的預留顯示「已提醒」時間，通知紀錄多一筆提醒

### S8 解除綁定後手機登入失效
**誰／哪裡**：工讀生後台 → 陳師傅手機
1. 工讀生：客戶 → 大發電器行 → 解除綁定
2. 陳師傅：在手機上點任何頁面

**預期**
- [ ] 陳師傅被導回登入頁，無法再看到訂單
